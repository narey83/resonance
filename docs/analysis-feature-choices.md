# Selected enhanced analysis and auto cues

Track Analysis offers full enhanced analysis or a selected set of measurements for either a single row or the current selection. The API accepts `enhancedFeatures` only with `enhanced: true` and requires explicit selected paths for this option or auto cue writing. A null list retains the full USB-ready contract. A selected list is checked against the worker's supported measurements; dependencies are enabled by `CandidateFeatureSelection.Apply`. Basic BPM, key, loudness and waveform analysis still runs first. Candidate results are reused only when the source is current, the result covers the full track and every requested feature is available. Bulk scans discard large stem audio after analysis; the separate on-demand stem preview retains its requested files.

`writeAutoCues` is an explicit option on a selected enhanced scan. The server takes the cue owner from the authenticated session and never accepts it from the request body. It saves up to eight current cue proposals in that user's track preparation, with IDs prefixed `resonance-auto-cue:`. Manual bookmarks and notes survive regeneration. Proposals within one second of a manual bookmark are skipped. Re-running the option replaces only previous auto cues. Errors are counted against the selected track and logged.

USB export includes only that user's saved auto cues as hot cue slots 1–8. The Python exporter writes them into the `PCOB` cue lists in `.DAT` and `.EXT` and the `PCO2` list in `.EXT`; it parses those files again to verify slot and millisecond position. The OneLibrary database's cue table remains reserved for memory cues and loops. This follows the [Deep Symmetry ANLZ structure](https://github.com/Deep-Symmetry/crate-digger/blob/main/src/main/kaitai/rekordbox_anlz.ksy). The independent parser test establishes file structure, not OPUS-QUAD hardware behavior; a physical player check remains necessary before relying on the cues for a performance.
